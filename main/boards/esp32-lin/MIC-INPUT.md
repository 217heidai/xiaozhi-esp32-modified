# ESP32-LIN 双麦克风输入处理建议（2026-11-12）

## 硬件事实（原理图第 3 页）

- 两个麦克风接口 `J2L1` / `J2R1`，各走一对差分线 `L1_P/L1_N`、`R1_P/R1_N`，分别进 WM8978 的**左 / 右输入 PGA**（LIP/LIN、RIP/RIN）
- `MIC_PWR` 经 R38 / R39（0 Ω）给两路麦克风偏置
- 3.5 mm 耳机座 J2（PJ-320B-A）只有 L/R 输出，**没有 MIC 脚**；右上 3 针座是 L2/R2/AUX 线路扩展，不是麦克风
- 厂商 BSP 也是按双路 MIC 配置的：`WM8978_Input_Cfg(1,0,0)` 启用左右 boost，`WM8978_MIC_Gain(25)` 同时写 reg45（左 PGA）与 reg46（右 PGA）

结论：板上是**两个独立麦克风、左右各一路差分输入**，不是「板载 + 耳麦」二选一，也不需要检测切换。

## 历史状态（已改为混合）

- 早期版本 I2S 收立体声但 `Read()` 只取 `AUDIO_CODEC_INPUT_RIGHT_CHANNEL`（`0` = 左，`1` = 右），另一路数据被丢弃；2026-11-12 起改为 `AUDIO_CODEC_INPUT_MODE=2` 混合。

## 方案对比

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| 只取一路 | 当前实现 | 最简单、无相位风险，但浪费一个麦；调试阶段有用 |
| **左右混合 `(L+R)/2`** | **推荐** | 单声道输出贴合 ASR / 唤醒词；两路拾音都利用，不相关噪声约降 3 dB |
| 立体声双通道上行 | 不建议 | 服务端与编码器按单声道设计；`input_channels_=2` 会牵扯协议与 AEC 语义 |
| 一路当 AEC 参考 | 不建议 | 参考信号应取自功放输出，两个麦都是拾音，语义不对 |
| 双麦波束成形 / 降噪 | 暂不建议 | 音频框架无现成组件，ESP32 算力与内存紧张，学习阶段投入产出比低 |

## 推荐实现

- 默认混合，保留可切换能力：`config.h` 的 `AUDIO_CODEC_INPUT_MODE`（`0` = 只取左，`1` = 只取右，`2` = 混合，默认 `2`）
- `Read()` 用 `int32_t` 相加再除以 2，避免 `int16_t` 溢出：

```cpp
dest[i] = (int16_t)(((int32_t)rx_buffer_[2 * i] + (int32_t)rx_buffer_[2 * i + 1]) / 2);
```

- 风险：两个麦挨得近，声源偏离中轴时两路有相位差，直接相加可能产生梳状滤波（声音发空、识别率下降）。
  语音频段波长较长（4 kHz 约 8.5 cm），一般没事；一旦出现就切回单路。

## 建议的验证顺序

1. 只取左说一句、再只取右说一句，对比哪路灵敏、哪路串功放回声
2. 切混合，对比唤醒词命中率与 ASR 识别率
3. 保留宏，后续换麦克风位置或改板不用重写驱动

## 已落地（2026-11-12 08:55）

- 用户确认「耳机两边均有声音 / 麦克风改两路混合 / 修复启动超时」后实现：`AUDIO_CODEC_INPUT_MODE=2`、`Read()` 用 `int32_t` 求平均、`EnableInput(true)` 先拉起 TX 并在录音期间保持 TX 不关。
- 增量编译 + 只烧 app 分区，Wi-Fi / 激活 / 中文配置不变；启动日志应显示 `input mix`，且不再出现 `I2S read failed or timed out`。
- 验收记录见 `VERIFY-final.md`。

## 听感验收通过（2026-11-12 09:10）

- 用户完成混合模式下的完整对话（唤醒词 → ASR → MCP 音量 → TTS → 退出），确认**主观听感「没有别扭」**：无发空、变糊或双麦相位干涉。
- 结合日志证据（零 I2S 错误、唤醒词命中、识别未劣化），`AUDIO_CODEC_INPUT_MODE=2` 定为最终配置，混合方案闭环。
- `0` / `1` 单路开关保留作保底，后续改板或换麦克风布局时再评估。
